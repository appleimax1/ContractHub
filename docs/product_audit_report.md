# 📊 Продуктовый отчет (Product Audit Report) — DocGen PRO MVP

**Автор:** Lead Product Manager  
**Продукт:** DocGen PRO (Standalone Offline Document Generator)  
**Статус MVP:** Собрана функциональная веха-версия (v0.1.0-alpha)  
**Дата аудита:** 31 июля 2026 г.

---

## 1. 🎯 Анализ соответствия Product Vision (Соответствие цели)

Изначальный **Product Vision** декларировал создание автономного (offline-first), универсального генератора документов, работающего **100% в браузере без сервера**.

### ✅ Что успешно достигнуто в MVP:
1. **100% Privacy-First & Offline**: Данные обрабатываются исключительно в `IndexedDB` браузера пользователя с помощью `Dexie.js`. Ни один договор или реквизит не покидает устройство.
2. **Движок шаблонизации с модификаторами (Pipes)**: Внедрен `docxtemplater` в связке с `angular-expressions`. Пользователи могут применять пайпы в стиле Angular/Jinja2: `{{ contract_date | date:'d.m.Y' }}` и `{{ sum | money:'words' }}`.
3. **Гибкая реляционная структура данных**: База данных разделена на "Мои Компании" (мои юрлица), "Базу Клиентов" (контрагенты) и "Кастомные поля", что избавляет пользователя от дублирования ввода.
4. **Конструктор полей с мгновенным Copy-Paste**: Позволяет не-программисту сгенерировать правильный тег и скопировать его одной кнопкой для вставки в MS Word.
5. **Локальная PDF-конвертация**: Интегрирован стек `mammoth.js` (docx → html) + `html2pdf.js` (html → pdf), позволяющий генерировать PDF файлы оффлайн.

## 2. 🔍 Аудит UX / UI и Пользовательских сценариев (User Journey)

### Текущий сценарий работы пользователя:
1. Пользователь добавляет свою компанию в **«Мои Компании»**.
2. Пользователь добавляет контрагента в **«Базу Клиентов»**.
3. В **«Конструкторе полей»** создает недостающие динамические переменные (например, `Сумма договора`, `Срок оплаты`) и копирует готовые теги в свой Word-шаблон.
4. В **«Генераторе»** загружает `.docx`, выбирает компанию и клиента из выпадающих списков, заполняет пару полей и нажимает «Скачать .docx» или «Скачать .pdf».

## 3. ⚠️ Замечания, узкие места и найденные недоработки в MVP

В ходе анализа исходного кода и UI-структуры текущей версии выделены следующие критические продуктовые и технические замечания:

### 🔴 1. Отсутствие интерфейса для печатей и подписей (Критическая функция из PV)
* **Проблема:** В `product_vision.md` и в движке `TemplateEngine.ts` заложена поддержка `docxtemplater-image-module-free` для вставки прозрачных сканов печатей (`{{%stamp}}`). Однако в UI страницы **«Мои компании»** временно отсутствует элемент загрузки файла (File Upload) для изображения печати и подписи.
* **Влияние на UX:** Пользователь пока не может автоматически проставить печать на сгенерированный документ.

### 🟡 2. Ограничения конвертации DOCX → PDF (`mammoth.js` + `html2pdf.js`)
* **Проблема:** `mammoth.js` предназначен для конвертации текста и базовых таблиц в чистый HTML. При этом **теряется сложное форматирование Word**: специфические отступы, колонтитулы, нумерация страниц, границы таблиц и точный шрифт (Times New Roman и т.д.).
* **Влияние на UX:** PDF на выходе может визуально отличаться от оригинала `.docx`. 
* **Решение для v1.1:** Нативно использовать скачивание в `.docx` как основной формат, а для идеального PDF в будущем рассмотреть подходы через `pdf-lib` (наложение текста прямо на PDF-бланк) или использование стандартизированных CSS-стилей для печатных форм (`@page`).

### 🟡 3. Отсутствие конструктора табличных данных / циклов в UI
* **Проблема:** Движок поддерживает циклы `{%for item in schedule%}`, однако **«Конструктор полей»** позволяет создавать только скалярные поля (`string`, `date`, `number`, `money`).
* **Влияние на UX:** Если пользователю нужно сгенерировать Спецификацию или График платежей (таблицу товаров/услуг с динамическим числом строк), он не сможет настроить такое поле через UI без ручной подготовки массива данных.

### 🔵 4. Отсутствие истории сгенерированных документов
* **Проблема:** В схеме БД `db.ts` создана таблица `document_history`, но в компоненте `GeneratorPage.tsx` событие генерации не записывается в истории, и нет раздела UI для просмотра ранее сгенерированных документов.

### 🔵 5. Мелкие UX-улучшения (Micro-UX)
* **Валидация синтаксиса:** Если пользователь загрузит `.docx` с синтаксической ошибкой в теге (например, не закрыл скобку `{{ name`), приложение покажет общий `alert`, вместо подсвечивания конкретной строки/тега с ошибкой.
* **Предпросмотр (Preview):** Перед скачиванием нет интерактивного предпросмотра заполненного документа.

## 4. 🚀 Рекомендации и Дорожная карта (Product Roadmap)

Для превращения MVP в готовую коммерческую версию рекомендую следующий порядок спринтов:

### 🔹 Спринт 1: Завершение баг-фиксов MVP (Полировка)
1. **Загрузка печатей и подписей**:
   - Добавить на страницу «Мои компании» загрузку PNG/SVG файлов (Печать, Подпись директора).
   - Сохранять их в `IndexedDB` в формате Base64 / Blob.
   - Передавать `company.stamp` и `company.signature` в пайплайн `docxtemplater-image-module`.
2. **Логирование истории документов**:
   - При каждом нажатии на «Скачать» сохранять запись в `document_history` (кто, когда, по какому шаблону сгенерировал).

### 🔹 Спринт 2: Расширение возможностей шаблонизации (v1.1)
1. **Поддержка табличных полей (Repeating Groups / Tables)**:
   - Добавить в «Конструктор полей» тип поля `Таблица / Список товаров`.
   - В Генераторе рендерить динамический формовый блок с возможностью добавления строк (`+ Добавить позицию`: Наименование, Количество, Цена, Сумма).
2. **Интерактивный предпросмотр (Live Preview)**:
   - Встроить просмотрщик документа на страницу Генератора справа от формы ввода.

### 🔹 Спринт 3: Импорт / Экспорт и Резервное копирование (v1.2)
1. **Резервное копирование БД**:
   - Функция «Экспорт всей базы в JSON» и «Импорт базы» для переноса данных между браузерами или компьютерами сотрудников.
